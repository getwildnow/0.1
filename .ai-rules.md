## 📝 WORKFLOW RULES

### Before Making Changes
1. Read existing code to understand current implementation
2. Check if feature exists or conflicts with team work
3. Ask user if unsure about modifying shared code
4. Use `grep` or `codebase_search` to find related code

### When Adding Features
1. Create new files/components instead of modifying existing ones when possible
2. Use consistent naming conventions
3. Follow existing patterns in the codebase
4. Test locally before committing

### Git Workflow
1. Always commit with clear, descriptive messages
2. Clean up temporary test files before committing
3. Push to `getwild-app` branch
4. Remove credentials from git remote after push
